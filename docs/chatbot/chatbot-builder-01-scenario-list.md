# CBB-01 시나리오 목록 기능명세

## 1. 목적과 진입 조건

등록된 챗봇 시나리오를 검색하고 생성·수정·복제·삭제하며 편집 화면으로 진입한다. 화면 진입 즉시 기본 검색조건으로 목록을 조회한다.

## 2. 화면 구성

| 영역 | 구성요소 | 설명 |
|---|---|---|
| 좌측 | UI 사이드바 | `UI_DEEP` 메뉴. 항목 클릭 시 목록을 재조회한다. 추가 버튼은 숨김 처리된다. |
| 상단 | 검색/정렬 영역 | 정렬, 기간, 배포상태, 이름, 초기화, Search |
| 본문 | 카드 그리드 | 신규 카드와 시나리오 카드. 최소 카드 폭 252px, 스크롤 가능 |
| 팝업 | Edit Scenario | 신규 생성 또는 선택 시나리오 정보 수정 및 편집 화면 진입 |

## 3. 검색 및 정렬

| 항목 | 값 | 처리 규칙 |
|---|---|---|
| Sort Order | Last Updated | `updated_at` 내림차순, 값 없음은 가장 과거로 취급 |
|  | Name | 이름을 한국어 locale, 대소문자 비민감 기준 오름차순 |
|  | Last Deployed | 배포된 항목 우선, 배포 버전 내림차순; 미배포끼리는 수정일 내림차순 |
| Period | All | 기간 필터 없음 |
|  | Today | 오늘 00:00 이후 수정된 항목 |
|  | 1 Week | 현재 시각 기준 7일 이내 수정된 항목 |
| Deployment Status | All | 전체 |
|  | Deployed | `depn_ver_id`가 있는 항목 |
|  | Not Deployed | `depn_ver_id`가 없는 항목 |
| Name | 자유 입력 | Enter 또는 Search로 조회 요청에 전달 |

- 셀렉트 값 변경 시 즉시 재조회한다.
- 초기화 버튼은 편집 팝업을 닫고 검색 폼을 기본값으로 되돌린 후 재조회한다.
- 검색 영역의 빈 공간을 클릭하면 선택/편집 상태만 해제한다.
- 서버 조회 결과에 대해 화면에서 정렬, 배포상태, 기간 필터를 추가 적용한다.

## 4. 시나리오 카드

- 카드에는 배포 버전(`v.{depn_ver_id}`), 수정일시, 이름, 더보기 메뉴를 표시한다.
- 배포된 카드는 연한 녹색 배경으로 구분한다.
- 단일 클릭: 카드를 선택하고 Edit Scenario 팝업을 연다.
- 더블클릭: 해당 시나리오를 Store에 설정하고 플로우 편집 화면으로 이동한다.
- 더보기 메뉴: Clone, Edit, Delete.

## 5. 신규 생성

1. `New Job` 카드를 클릭한다.
2. 목록 맨 앞에 ID가 없는 임시 시나리오를 추가하고 생성 팝업을 연다.
3. Name과 Description을 입력한다. 생성 모드에서만 Name을 수정할 수 있다.
4. Save 수행 시 입력값으로 생성 API를 호출한다.
5. 성공 응답을 현재 시나리오로 설정하고 모드를 Edit로 전환한 뒤 목록을 갱신한다.

제약:

- ID 없는 임시 시나리오가 이미 목록에 있으면 New Job 클릭은 무시된다.
- 현재 코드에서 필수 표시(`Name *`)는 있으나 별도의 폼 validation 규칙은 선언되어 있지 않다.

## 6. 조회 및 수정 팝업

| 필드/버튼 | 생성 모드 | 수정 모드 |
|---|---|---|
| Name | 입력 가능 | 읽기 전용 |
| Description | 입력 가능 | 입력 가능 |
| Created/Updated/Last Used | 빈 값 | 포맷된 일시 표시 |
| Edit | 저장된 ID가 있을 때 편집 화면 이동 | 편집 화면 이동 |
| Save | 생성 API | 이름·노드·엣지·시작노드를 제외한 데이터 Patch |

- 수정 모드 진입 시 상세 API를 호출해 폼을 다시 채운다.
- 입력 변경은 폼과 목록의 해당 카드 데이터에 동시에 반영한다.
- 팝업 외부/닫기 동작은 편집 모드와 선택 상태를 해제한다.

## 7. 복제와 삭제

### 복제

- 원본 상세를 조회한 뒤 `clone_from_id`에 원본 ID를 넣는다.
- 신규 ID는 빈 값으로 만들고 이름은 `[clone]_{원본명}`으로 생성한다.
- 복제 API 완료 후 목록을 재조회한다.

### 삭제

- 선택 시나리오 ID를 배열로 전달해 삭제 API를 호출한 뒤 목록을 재조회한다.
- 현재 화면 코드에는 삭제 전 확인 팝업이 없다.

## 8. 예외 및 QA 확인사항

- 목록 조회 실패 시 로딩을 종료하고 오류를 발생시키며 상위 처리에서 브라우저 alert를 표시한다.
- 저장 성공 Snackbar의 문자열이 현재 소스 인코딩상 깨져 있어 실제 노출 문구 확인이 필요하다.
- `last_used_at`은 상세 응답의 `updated_at`으로 표시된다.
- 버전 조회 이동 함수는 정의되어 있으나 현재 카드에 콜백이 연결되어 있지 않다. 실제 UI 진입 경로 확인이 필요하다.
- Save 버튼의 실제 렌더링/문구는 팝업 하단 구현과 번역 리소스를 함께 확인해야 한다.
