# AI Admin Console 폼 빌더 기능 명세

## 1. 문서 목적과 판정 기준

이 문서는 `src/app/builder/form-builder`의 현재 소스 코드를 기준으로 구현된 기능을 정리한다. 화면에 설정 항목이 존재하는 경우와 실제 런타임 동작이 연결된 경우를 구분했으며, 백엔드·배포 인프라까지 확인되지 않은 기능은 확정적으로 표현하지 않는다.

기능 상태는 다음 기준을 사용한다.

| 상태 | 의미 |
|---|---|
| 구현 | 현재 모듈에서 UI와 상태/동작이 연결됨 |
| 부분 구현 | 설정 또는 데이터 모델은 있으나 실행 범위가 제한됨 |
| 확장 기반 | 타입·슬롯·레지스트리 등 후속 확장에 활용 가능한 구조 |
| 미확인 | 현재 모듈만으로 제공 여부를 판단할 수 없음 |

## 2. 기능 요약

현재 폼 빌더는 React/Next.js 기반의 비주얼 편집기로, 7종 컴포넌트의 드래그앤드롭 조립, 속성 편집, JSON 양방향 편집, API 이벤트와 타깃 컴포넌트 매핑, 서버 저장/불러오기를 지원한다. 범용 폼 플랫폼 전체보다는 **AI 시나리오 안에서 데이터 입력·조회·표시 UI를 빠르게 구성하는 도메인 특화 빌더**에 가깝다.

핵심 차별점은 다음과 같다.

- 검색 API 결과를 슬롯에 저장하고 그리드에 연결하는 데이터 흐름 모델
- 컴포넌트 이벤트에서 사전 등록 API를 호출하고 다른 컴포넌트에 응답을 반영하는 연계 기능
- 비주얼 편집 결과와 JSON을 즉시 상호 반영하는 양방향 편집
- 사용자별 미사용 컴포넌트를 제외하는 노출 제어
- 기존 Builder 노드 체계에서 사용할 수 있는 고정 크기 `FormDataJson` 산출물

## 4. 지원 컴포넌트

### 4.1 공통 속성

모든 요소는 고유 ID, 유형, 이름, 라벨을 가진다. 이름은 슬롯 키로 사용할 수 있다. 요소별로 API ID/메타데이터, 이벤트 유형, 요청 파라미터, 추가 JSON 파라미터, 대상 요소, 응답 경로를 설정할 수 있다.

| 속성 | 용도 |
|---|---|
| `id` | 요소 고유 식별자; 자동 생성 및 읽기 전용 표시 |
| `name` | 데이터/템플릿에서 참조할 슬롯 키 |
| `label` | 화면 표시명 |
| `apiId`, `apiData` | 사전 등록된 API 선택 결과 보관 |
| `eventType` | `onChange` 또는 `onClick` API 실행 조건 |
| `parameterId` | 현재 요소 값을 쿼리 파라미터로 전달할 키 |
| `optionalParameter` | 다른 요소 ID/이름을 `{{key}}`로 치환하는 JSON 요청 본문 |
| `targetElementId` | API 응답을 반영할 대상 요소 |
| `responsePath` | 점 표기와 배열 인덱스를 지원하는 응답 추출 경로 |

### 4.2 요소별 기능

| 컴포넌트 | 제공 기능 | 상태 |
|---|---|---|
| Text Field | 기본값, 플레이스홀더, text/email/number/custom 검증 유형, 슬롯 값 참조 안내 | 구현(검증 유형 설정); 실제 제출 검증 실행은 미확인 |
| Date Field | 날짜 기본값 설정 및 날짜 입력 미리보기 | 구현 |
| Checkbox | 0~20개 옵션, 표시명과 실제 값 분리, 복수 기본 선택 | 구현 |
| Radio | 0~20개 옵션, 표시명과 실제 값 분리, 단일 기본 선택 | 구현 |
| Dropbox | 단일/다중 선택, 옵션 편집, 기본 선택, 동적 옵션 슬롯 | 구현 |
| Grid | 행/열 크기 변경, 최대 20 기준의 입력 UI, 셀 직접 편집, 데이터 슬롯, `key:label` 표시 열 구성 | 구현 |
| Search | GET/POST, URL, JSON 헤더, 요청 본문 템플릿, 결과 슬롯, 선택 행의 입력 채움 키 | 구현(설정/미리보기); 이 모듈 내 독립 검색 네트워크 실행 여부는 별도 런타임 확인 필요 |

컴포넌트 정의는 중앙 레지스트리에서 기본값·아이콘·생성 함수를 관리한다. 타입 목록은 표시 여부, 정렬 순서, 삭제 여부를 갖는 메타데이터로 관리되며 사용자 정보의 `unuse_form_elements`를 반영해 팔레트와 편집 가능 범위를 제한한다. 현재 타입 목록은 코드 내 초기 데이터이며 `/chat/form-element-types` 전환 지점이 주석으로 남아 있다.

## 5. 데이터, JSON 및 동적 연계

### 5.1 JSON 기반 폼

- 폼은 `FormDataJson` 구조로 직렬화된다.
- JSON 탭에서 유효한 JSON을 입력하면 제목, 요소, 데이터 소스 설정이 즉시 미리보기에 반영된다.
- 잘못된 JSON은 오류 메시지를 표시하고 기존 편집 상태를 유지한다.
- 불러온 값은 허용된 7개 요소 유형만 수용하며 누락되거나 잘못된 속성은 유형별 기본값으로 정규화한다.
- JSON은 원본 들여쓰기 또는 한 줄 형식으로 클립보드에 복사할 수 있다.
- 저장 시 옵션의 표시명과 값이 동일하면 단순 문자열로 축약해 호환성을 유지한다.

대표 산출 구조는 다음과 같다.

```json
{
  "id": "form-...",
  "data": {
    "id": "form-...",
    "title": "new form",
    "elements": [],
    "dataSource": "",
    "dataSourceType": "json",
    "enableExcelUpload": false
  },
  "type": "form",
  "width": 320,
  "height": 597,
  "dragging": false,
  "selected": false
}
```

### 5.2 API 이벤트 및 응답 매핑

API 연계는 소스 요소 → 이벤트 → API → 응답 경로 → 타깃 요소의 흐름으로 구성된다.

1. API 목록 대화상자에서 사전 등록 API를 선택한다.
2. `onChange` 또는 `onClick` 실행 조건을 지정한다.
3. 현재 값은 `parameterId` 이름의 쿼리 파라미터로 전달할 수 있다.
4. `optionalParameter` JSON 안의 `{{요소ID}}` 또는 `{{요소이름}}`을 각 요소 기본값으로 치환한다.
5. 응답에서 `responsePath`를 추출한다. 경로가 없으면 `data`, `result`, `items`, `list`, `rows`를 우선 탐색한다.
6. 응답을 대상 요소 유형에 맞게 변환하여 기본값, 옵션 또는 그리드 데이터에 적용한다.

| 대상 요소 | 응답 적용 방식 |
|---|---|
| Text/Search | 첫 값 또는 객체의 대표 필드를 문자열 기본값으로 변환 |
| Date | 날짜를 `YYYY-MM-DD` 형식으로 변환 시도 |
| Checkbox | 배열/객체를 옵션 목록 및 복수 기본값으로 변환 |
| Radio | 옵션 목록과 첫 값을 기본 선택으로 변환 |
| Dropbox | 옵션 목록과 단일/복수 선택 모드에 맞는 기본값으로 변환 |
| Grid | 객체 키 또는 배열 위치로 열을 만들고 헤더/본문 셀 데이터 생성 |

편집기에서 API 단독 실행, 응답 JSON 확인, 실행 후 대상에 즉시 적용을 지원한다. 실제 캔버스 이벤트 실행은 선택된 API endpoint에 POST하고 결과를 지정 대상에 반영한다.

### 5.3 데이터 소스 확장 설정

폼 데이터에는 `dataSource`, `dataSourceType(json/api)`, `enableExcelUpload`가 포함된다. 이 설정은 UI/JSON/저장/불러오기 사이에서 보존된다. 다만 현재 모듈만으로 실제 Excel 파싱·업로드 처리와 폼 전체 데이터 소스 로딩 실행은 확인되지 않으므로 **부분 구현**으로 관리해야 한다.

## 6. 상태 관리와 무결성

- Zustand 단일 스토어에서 폼 ID, 제목, 요소 배열, 선택 요소, 요소 유형 메타데이터를 관리한다.
- 추가 직후 신규 요소를 선택하고, 삭제 시 선택 상태도 안전하게 해제한다.
- 순서 변경 시 존재하지 않는 ID와 동일 위치 이동을 무시한다.
- 그리드 크기 변경 시 기존 셀 값을 가능한 범위에서 유지하고 나머지를 빈 값으로 채운다.
- 옵션 개수가 줄면 유효하지 않은 Checkbox/Radio/Dropbox 기본값을 자동 제거한다.
- 저장 데이터와 직접 입력 JSON은 정규화 과정을 거쳐 레거시 문자열 옵션과 `{value,label}` 옵션을 모두 수용한다.

## 7. 현재 범위와 제한사항

다음은 `form-builder` 소스에서 완결된 기능으로 확인되지 않는다.

- 다단계/페이지 위자드와 페이지 간 조건 분기
- 필수값, 길이, 정규식, 교차 필드 등 실제 제출 시 유효성 검증 엔진
- 제출 데이터의 별도 저장, 자동 저장, 이어쓰기, 동시 편집 충돌 제어
- 오프라인 입력 및 복구 후 동기화
- 이메일·웹훅·역할 변경 등 범용 사후 액션 워크플로우
- PDF 생성/템플릿, 전자서명, 통계·리포팅, 범용 데이터 내보내기
- 폼 버전 이력, 감사 로그, 롤백
- 접근성 준수 인증, 반응형 품질 기준 및 자동 검사
- CSS 테마 편집기, 화이트라벨 임베드 SDK
- 테넌트/팀/역할/제출 데이터 단위 권한
- MCP 서버, 에이전트 스킬, 운영용 Agent Gateway

이 항목들은 제품 전체의 다른 모듈이나 인프라에서 제공될 수 있으나, 본 문서의 코드 조사 범위에서는 **미확인**이다.

## 8. 제안 수용 기준

고객 설명과 WBS 산정 시 다음 경계를 명시한다.

- “폼 빌더 제공”은 현재 7개 요소, 속성 편집, JSON, API 연계, 저장/불러오기 범위를 의미한다.
- Form.io의 전체 기능 목록은 단일 기능이 아니라 폼 런타임, 제출 데이터 플랫폼, 워크플로우, 보안, 운영 도구를 포함한 제품군이다.
- 추가 기능은 이름만으로 산정하지 않고 사용자 시나리오, 데이터 모델, 권한, 감사·보안, 배포 형태, 수용 기준을 각각 확정한 뒤 별도 WBS로 관리한다.
- 설정 UI만 존재하는 데이터 소스/Excel 옵션은 실행 기능 검증 후 납품 범위에 포함한다.
